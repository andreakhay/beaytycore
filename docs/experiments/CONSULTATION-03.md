# CONSULTATION-03 conversational recommendation evidence

Date: 2026-09-30. Status: **IN PROGRESS; LOCAL/MOCKED VERIFIED; LIVE GEMINI NEEDS VERIFICATION**.

## Implemented boundary

`CONSULTATION_PROVIDER=deterministic` retains the CONSULTATION-02 structured form and its deterministic provider. `CONSULTATION_PROVIDER=gemini` changes only the consultation preference/recommendation stage. `GET /consultations/mode` tells the existing page which experience to show. `POST /consultations/{id}/turn` serializes a short text conversation in the existing bounded consultation store, updates structured preferences, and returns either `more_information` with one assistant question or `ready_for_recommendation` with three backend-validated recommendations. On an invalid or failed provider result, no messages, preferences, or recommendations from that turn are committed. The existing sequential generation cards, feature dispatcher, Hair/Makeup/Nails handlers, unified Kaggle worker and Custom routes are unchanged.

The SDK request uses `gemini-3.8-flash` by default, configurable with `CONSULTATION_GEMINI_MODEL`. `GEMINI_API_KEY` is read only by FastAPI. Calls have one SDK attempt, 30-second HTTP timeout and 35-second outer timeout. There is no silent deterministic fallback. The installed Google GenAI SDK is pinned to `google-genai==2.7.0`. The SDK's documented default retry behavior is overridden with `HttpRetryOptions(attempts=1)`. Its full `response_json_schema` field is used because the strict Pydantic contract's `additionalProperties` is rejected by the API's narrower `response_schema` field. Backend Pydantic and the existing recommendation validator remain authoritative.

Only primary service, prior text messages, current structured preferences, the latest user text and compact eligible style IDs/names/tags/descriptions are sent to Gemini. No photo or generated image, price/duration, adapter, prompt, model path, Kaggle credential or internal path is included. Gemini may propose `status`, `assistant_message`, preference fields and style choices/reasons/complements. The backend validates exactly three distinct active primary styles, feature/style pairing, exclusions and complements; then attaches authoritative names, demo-only PHP price/duration and Nails model/renderer metadata. Complementary images are not generated.

The browser test covers Gemini-mode conversation through three existing result cards and a retriable opening-question failure. The deterministic Consultation and manual feature tests remain in the regression suite. No GPU call is required.

In the active mock catalog used for local tests, the validator accepted three distinct Hair IDs (`crew-cut`, `textured-crop`, `curtain`), Makeup IDs (`natural_makeup`, `no_makeup_makeup`, `soft_glam`), and Nails IDs (`classic_red`, `nude_pink`, `glossy_black`). These IDs were returned by the inspected mock catalog; they are not claims about live Gemini's choices or the deployed trained-style registry. The corresponding tests assert `validated=True` behavior, backend demo-only service estimates and that generation has not started until the existing per-card flow requests it. The separate one-answer test accepts “I don't care about length” without another mandatory question.

Automated results: `cd backend; python -m pytest tests -q` **404 passed** (one existing `python_multipart` deprecation warning). `cd frontend; npm run lint` and `npm run build` passed. ## Live provider attempt and limitation

The key was configured locally by the Supervisor and was never printed. A minimal `gemini-3.8-flash` text request succeeded, confirming model/key access. The first SDK async request used its default aiohttp path and failed DNS resolution (`ClientConnectorDNSError`) in this local environment, while an unauthenticated async HTTPX request reached the same API host. The provider now supplies an HTTPX async client through the SDK's supported `HttpOptions` field. The next request reached Google and returned HTTP 400 because `response_schema` could not accept strict `additionalProperties`; this was changed to `response_json_schema`. Subsequent structured requests returned Google HTTP 503 with a “high demand” message. A tiny one-property structured request also returned 503, as did temporary configured probes of other listed Flash models; plain unstructured text against the target model succeeded. This does not identify the underlying reason for structured-output 503. The application classified the failures safely as provider errors; no recommendation was saved and no generation started. **No successful live conversational recommendation has yet been observed.**

The reproducible text-only probe is `python ../scripts/consultation03_live_probe.py` from `backend/`. It creates three bounded consultations using one synthetic 128×128 PNG per case, sends representative graduation/clean/low-maintenance, casual/natural/subtle and bold event/avoid-black messages, then checks backend-validated styles and confirms generation remains pending. Its optional `--feature` flag runs one case. It prints only synthetic conversation, structured preferences, style IDs and reasons; no key, real photo, endpoint or image bytes.
