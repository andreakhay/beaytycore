## Decision and implementation

[Decision before implementation](../specs/0002-capstone-startup.md): a signed temporary HTTP record on ntfy.sh. No existing registry was evidenced. No account or extra credential; topic and signature use separate HMAC domains derived from the existing API key. Only safe URL/version/bundle/status/expiry/publication metadata is published. API key never goes to ntfy. Latest message only, four-hour validity, signature and schema checks, strict Quick Tunnel root, then public and authenticated worker health verification. No local URL cache or older-record fallback. Unknown/private request state and generation retry decisions remain unchanged.

The free mailbox is a demo dependency: cached messages expire and availability/rate limits are external. Failure is explicit; manual override is opt-in and still validates the worker. Starting/failed records invalidate earlier publications when service is reachable. A mailbox outage does not cause inference duplication; the GPU bootstrap can finish for an explicit manual override but does not report CAPSTONE_AI_READY until publication/readback succeeds. Sources: [publish/cache](https://docs.ntfy.sh/publish/), [latest polling](https://docs.ntfy.sh/subscribe/api/), [privacy](https://docs.ntfy.sh/privacy/).

`scripts/capstone_kaggle.py` stages package verification, unchanged exact bootstrap, protected public readiness and signed publish/readback. Re-entry verifies its own extracted bytes and current idle worker before republishing, no second bootstrap/Base load. Bootstrap failures retain specific safe stages, original logs and reports. `scripts/make_capstone_notebook.py` creates a thin pinned entry cell plus an optional evidence-only cell. Public repository raw-file access verified HTTP 200 at the Deployment-01 commit; final support pins will be checked after push. No new private bundle was created. Existing 128,962,896-byte private package remains SHA `68f6c9eb2bc0ce12b2c9c6d89e33f22898fb201b33a792887f6c5967ad16ec4e`.

`scripts/capstone_launch.py`, root START/STOP batch files: discover/verify, runtime environment override without `.env` writes, hidden supervisor/backend/Next dev children, backend readiness then frontend HTTP and final central readiness. Existing verified system Python and Node dependencies are reused. A short Windows file lock prevents competing starts. Authenticated loopback controller + Windows Job Object identify owned sessions; same session reuses, changed owned session stops/replaces; unmanaged occupied ports fail without killing. Supervisor death/STOP closes its own process tree. [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). Safe local `startup.json` contains publication/session IDs, fingerprint and startup duration; private controller token is not evidence. Logs/evidence stay ignored.
